# 项目概览

## 1. 项目定位

本项目是一个面向海上无人艇编队电磁兼容分析的桌面仿真工程，主体为 `Qt + C++ + CMake` 应用。
当前主仓的职责主要有三项：

- 组织输入配置与 UI 交互
- 将配置转换为 `DataModel`、`Fleet` 等内部对象
- 基于 `PE-PLST` 传播链路计算二维场强或路径损耗结果

`PE_validation` 已从主仓拆分为独立 Git 子模块，用于保存实验设计、notebook、图表和论文式验证结论。它是验证侧资产，不是主程序运行时依赖。

## 2. 当前状态

### 当前已实现

- 主程序采用统一的新 JSONC schema 输入，活动样例为 `Tests/Test.jsonc`。
- `EnvironmentData` 的主要参数已由配置文件驱动，不再只依赖 `DataModel.h` 中的硬编码默认值。
- `JsonLoader` 使用 `Interface/SchemaConstants.h` 约束字段名、固定值和枚举值，并按严格 schema 解析。
- 主程序可以完成 `DataModel -> Fleet -> EMC_Engine / PEModel` 的二维传播计算，并在 UI 中显示结果。

### 验证侧已有

- `PE_validation` 子模块中已沉淀实验 1 到实验 3 的 notebook、设计说明、汇总文档和 HTML 结果。
- `Two-Ray / FDTD / PE-PLST` 的验证口径，以及 A/B 编队实验指标结论，主要保存在验证侧资产中。

### 建议后续实现

- 将实验 3 的 EMC 指标正式迁移到主程序。
- 取消 `Simulation.cpp` 对测试文件的绝对路径依赖，改为仓库相对路径或 UI 选择。
- 把阵型模板、报告生成、统一结果对象等能力纳入主链路。

## 3. 目录职责

| 目录 | 作用 |
| --- | --- |
| `Interface/` | `DataModel`、快照结构、schema 常量、数据转换接口 |
| `Simulation/` | 传播计算、环境模型、PE 求解与 EMC 调度 |
| `Models/` | 船只、设备、天线、编队等领域对象 |
| `Utils/` | `JsonLoader`、绘图辅助、换算与通用工具 |
| `Resource/ui/` | Qt 页面、按钮、图表显示与仿真启动入口 |
| `Tests/` | 主程序配置样例，当前以 `Test.jsonc` 为主 |
| `docs/` | 项目概览、架构/API、风险、schema 和路线图文档 |
| `PE_validation/` | 验证侧子模块，保存实验 notebook、设计说明和结论汇总 |
| `.gitmodules` | 子模块声明，当前登记 `PE_validation` 的远端地址与分支 |

## 4. 主程序与验证侧的关系

主程序和验证侧并不是同一条运行链路：

- 主程序链路：`JSONC / UI -> DataModel -> TransferToEngine -> EMC_Engine / PEModel -> 结果显示`
- 验证侧链路：`实验配置 -> notebook / 图表 -> 论文式结论`

分析问题时应把两条链路一起看，但不能混淆状态。验证侧已有的结论，不等于主程序已经具备对应 API、界面或结果导出能力。

## 5. 当前输入标准

当前标准输入为新 schema，顶层结构固定为：

```json
{
  "schemaVersion": "1.0.0",
  "environment": {},
  "usvs": []
}
```

关键约定如下：

- 物理量统一使用 JSON `number`
- 船只集合使用 `usvs` 数组
- 设备集合使用 `transmitters` / `receivers` 数组
- `location.type` 固定为 `Point3D`
- 字段名、枚举值和固定字符串以 `Interface/SchemaConstants.h` 为准
