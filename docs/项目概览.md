# 项目概览
**注意: 不需要修改验证测代码,不需要处理验证测与主项目的兼容性,验证侧仅用于上下文参考**
## 1. 项目定位

本项目是一个面向海上无人艇编队电磁兼容分析的桌面仿真工程，主体为 `Qt + C++ + CMake` 应用。当前主仓职责主要有三项：

- 组织输入配置与 UI 交互
- 将配置转换为 `DataModel`、`Fleet` 等内部对象
- 基于 `PE-PLST` 传播链路计算二维场强或路径损耗结果

`PE_validation` 已从主仓拆分为独立 Git 子模块，用于保存实验设计、notebook、图表和验证结论。它是验证侧资产，不是主程序运行时依赖。

| `.gitmodules` | 子模块声明，当前登记 `PE_validation` 的远端地址与分支 |

## 4. 主程序与验证侧的关系

主程序和验证侧并不是同一条运行链路：

- 主程序链路：`JSONC / UI -> DataModel -> TransferToEngine -> EMC_Engine / PEModel -> 结果显示`
- 验证侧链路：`实验配置 -> notebook / 图表 -> 论文式结论`

分析问题时应把两条链路一起看，但不能混淆状态。验证侧已有的结论，不等于主程序已经具备对应 API、界面或结果导出能力。

## 5. 当前输入标准

当前标准输入为新 schema，顶层结构固定为：

```json
{
  "schemaVersion": "1.0.0",
  "environment": {},
  "emcAnalysisConfig": {},
  "usvs": []
}
```

关键约定如下：

- 物理量统一使用 JSON `number`
- `emcAnalysisConfig` 为顶层必填，统一承载结果平面高度与参考链路配置
- 船只集合使用 `usvs` 数组
- 设备集合使用 `transmitters` / `receivers` / `transceivers` 数组
- `location.type` 固定为 `Point3D`
- 字段名、枚举值和固定字符串以 `Interface/SchemaConstants.h` 为准

## 7. 2026-04-29 UI 主链路更新
### 当前已实现
- `Resource/ui/` 已补齐环境页、设备页、船只页的 `loadFromModel()/saveToModel()/setReadOnly()/dirty` 主链路。
- 主窗口工具栏已提供 `JSON/JSONC` 导入入口，导入成功后会统一写入 `DataModel` 并回填三类编辑页。
- 仿真页已改为显式任务状态机，运行时冻结单次任务快照，`EMC_Engine` 不再二次读取全局 `DataModel`。
- 仿真运行中会禁用环境/设备/船只编辑和导入入口，但仍允许只读浏览页面。
- `Home/TreeView` 已提供 `DataModel` 的只读总览，支持刷新、展开全部、折叠全部与关键字查找。
- `LogWidget`、`Home`、`DeviceonShip` 的关键稳定性问题已按主链路规格修复。

### 建议后续实现

- 当前取消仿真仍属于协作式停止，后续可继续结合传播计算热点细化中断点。
- `TreeView` 当前只读，不支持树节点编辑或页面跳转；如需产品化首页，可在后续单独设计。
- 结构化结果对象、任务历史与报告导出仍是下一阶段重点。
## 8. 2026-04-29 仿真结果边界更新
### 当前已实现
- 主程序已新增 `Interface/SimulationResult.h`，正式定义 `SimulationTaskResult`、`ScalarField2D`、`EmitterResult`、`DerivedMetrics` 与结果侧校验入口。
- `EMC_Engine` 已收敛为“多发射机计算与聚合引擎”，不再负责组装任务根结果对象。
- 原 `Propagation_Engine` 已拆为 `PEPropagationSolver`，职责收敛为单发射机 PE 求解。
- 新增任务级上下文 `simSchedulerCtx`，负责冻结输入快照、驱动 `EMC_Engine` 并组装 `SimulationTaskResult`。
- 仿真页已从直接消费 `GridMap` 调整为消费 `SimulationTaskResult`；绘图入口已支持 `ScalarField2D`。
- `DerivedMetrics` 已正式承载 `SCF / S3I / T_elev / D_desense`，并由独立的 `EMCMetricsCalculator` 在成功仿真后统一计算写回。
- `emcAnalysisConfig` 已进入主程序运行时链路，并跟随 `inputSnapshot` 一起保存在结果对象中。
- `docs/schema/` 下已新增 `simulation-result.schema.json` 与 `simulation-result.template.jsonc`，用于固定结果结构口径。

### 验证侧已有
- `PE_validation` 中的实验 3 指标定义、公式口径和图表结论仍保留在验证侧，可作为主程序实现与回归验证时的上下文参考。

### 建议后续实现
- 结果对象已能支撑 UI 多样化展示与报告生成入口，但任务历史、结果导出和报告模块仍未落地。
- `formationSource + presetFormationId` 字段已预留，后续需补齐“内置预设编队改造输入”的具体业务逻辑。
