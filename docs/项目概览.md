# 项目概览

## 1. 项目定位

本项目是一个面向海上无人艇编队电磁兼容分析的桌面仿真系统，当前形态为：

- `Qt6 + C++` 桌面应用：负责参数输入、场景组织、结果展示与日志输出。
- `PE-PLST` 传播计算内核：负责海面传播、波导环境下的电磁场损耗计算。
- `PE_validation/` 验证资产：负责实验设计、对比验证、图表生成和论文式结论沉淀。

从工程目标看，它既不是纯研究脚本仓库，也不是纯产品化 GUI 工具，而是处于“研究原型向工程化工具演进”的阶段。

## 2. 研究背景与技术路线

项目当前采用的主线技术路线可以概括为：

`Two-Ray -> FDTD -> PE-PLST -> 编队 EMC`

其含义如下：

- `Two-Ray`：作为平坦海面的解析基准，用于验证传播趋势是否合理。
- `FDTD`：作为小尺度场景下的全波参考解，用于对比 `PE-PLST` 的精度。
- `PE-PLST`：作为主项目中的高效传播模型，用于大尺度海面与粗糙边界传播分析。
- 编队 `EMC`：将传播结果进一步用于多艇编队内的系统级电磁兼容评估。

`PE_validation/实验1-3汇总.md` 已经把三组实验整理为一条完整证据链：

1. 实验一验证退化场景与网格收敛性。
2. 实验二验证 `PE-PLST` 相对 `FDTD` 的精度与效率。
3. 实验三验证在无人艇编队场景中的 EMC 指标体系与 A/B 对照结论。

## 3. 当前项目形态

当前仓库同时包含两套相互关联但尚未完全打通的体系：

### 3.1 主项目体系

- 以 `CMake + Qt6` 组织桌面应用。
- 使用 `DataModel` 承载 UI 输入。
- 使用 `JsonLoader` 读取 JSONC 场景配置。
- 使用 `TransferToEngine` / `TransferToPEdata` 转换为算法层对象。
- 使用 `EMC_Engine` 与 `PEModel` 完成传播仿真。

### 3.2 验证与论文体系

- `PE_validation/experiment1.ipynb`
- `PE_validation/experiment2.ipynb`
- `PE_validation/experiment3.ipynb`
- `PE_validation/DESIGN.md`
- `PE_validation/实验1-3汇总.md`

这套体系给出了实验口径、A/B 场景设计、四项 EMC 指标定义和图表结果，但其中一部分逻辑仍停留在 Python notebook 中，尚未完全迁移回主项目。

## 4. 目录职责

| 目录 / 文件 | 作用 |
| --- | --- |
| `Simulation/` | 数值计算核心，包括传播求解与 EMC 计算调度 |
| `Interface/` | DTO、数据快照、JSON 到算法层的转换、导出辅助 |
| `Models/` | 船只、设备、天线、编队等领域对象 |
| `Resource/ui/` | Qt 页面、主窗口和绘图组件 |
| `ModelView/` | 若干 Qt 视图模型与展示组件 |
| `ExamplePage/` | 示例页和 UI 演示代码 |
| `Utils/` | JSON 解析、绘图、单位转换、日志桥接等公共工具 |
| `Tests/` | JSONC 输入样例与 A/B 场景配置 |
| `PE_validation/` | notebook、实验文档、设计说明和结果图 |
| `third_party/` | 第三方代码与 UI 库 |
| `TODO.md` | 当前任务方向与中短期演进目标 |

## 5. 依赖与运行环境

当前主项目依赖如下：

- `Qt 6.9.3`
- `FFTW3`
- `Eigen3`
- `OpenMP`
- `spdlog`
- `ElaWidgetTools`

构建入口在 `CMakeLists.txt` 中，依赖管理通过 `vcpkg.json` 声明。当前工程里仍存在环境相关的硬编码路径，说明项目尚未完全从“个人开发机可运行”演进到“开箱即用的标准工程”。

## 6. 当前功能边界

### 6.1 已有能力

- 通过 UI 或 JSONC 配置描述船只、设备与基础传播参数。
- 将设备与舰船数据转换为算法层对象。
- 基于 `PEModel` 计算一维或二维传播损耗分布。
- 输出聚合后的二维功率分布图与 CSV 结果。
- 在 `PE_validation` 中完成实验一到实验三的验证和可视化。

### 6.2 尚未完全落地的能力

- 实验三四项 EMC 指标在主项目中的正式实现。
- 内置阵型模板与自动重排接口。
- 依据场景结果自动生成评估报告。
- 主程序与 notebook 结果口径的统一。

## 8. 建议的理解方式

在后续开发中，建议始终把本项目理解为以下三部分的组合：

- **产品壳层**：Qt 桌面应用与可视化界面。
- **算法核心**：`PE-PLST` 传播计算与后续 EMC 指标体系。
- **验证资产**：用于证明方法有效性的 notebook、实验说明和图表。

只有同时把这三部分联系起来，才能正确分析架构、整理接口规范，并判断哪些问题是“功能未做”，哪些问题是“口径未统一”，哪些问题是“验证侧已有但主程序尚未实现”。
