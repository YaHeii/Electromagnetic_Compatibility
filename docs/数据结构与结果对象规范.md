# 数据结构与结果对象规范

## 1. 文档目的

本文档用于固定项目中关键数据结构的职责边界和口径，避免后续实现、文档和测试出现分裂。

## 2. 输入侧结构

### 2.1 `DataModel::DataSnapshot`

`DataSnapshot` 是仿真任务冻结输入的标准结构，包含：

- `allEquipments`
- `allShips`
- `environmentConfig`
- `emcAnalysisConfig`

### 2.2 `request.json`

`Reportflow` 的请求文件用于描述报告任务本身，当前包括：

- `reportBundleVersion`
- `taskId`
- `mode`
- `language`
- `templateId`
- `outputFormats`
- `inputFiles`
- `assetFiles`

## 3. 中间结果结构

### 3.1 `EMCComputationResult`

`EMCComputationResult` 用于承接总场聚合后的中间结果，供后续指标计算使用。

### 3.2 `DerivedMetrics`

`DerivedMetrics` 用于承接当前四类派生指标：

- `SCF`
- `S3I`
- `T_elev`
- `D_desense`

## 4. 最终结果结构

### 4.1 `SimulationTaskResult`

这是仿真任务的统一根结果对象。

### 4.2 字段职责

- `taskId`：任务标识
- `modelType`：模型类型
- `status`：任务状态
- `formationSource`：编队来源
- `presetFormationId`：预设编队标识
- `startedAtUtcMs` / `finishedAtUtcMs` / `durationMs`：时间信息
- `errorMessage`：失败信息
- `summaryText`：摘要文本
- `inputSnapshot`：冻结输入
- `aggregatedField`：总场结果
- `emitterResults`：单发射机结果
- `derivedMetrics`：派生指标

## 5. 报告侧结构

### 5.1 `ReportJobBundle`

`ReportJobBundle` 是 C++ 与 Python 之间的兼容层，描述一次报告任务的目录布局。

### 5.2 固定目录

- `request.json`
- `simulation-result.json`
- `report-context.json`
- `status.json`
- `assets/`
- `outputs/`
- `logs/`

## 6. 口径约束

- 主程序结果对象不应直接回写为报告上下文
- Python 报告层不应修改仿真结果文件
- `presetFormationId` 目前保留为扩展字段，不应在文档中写成已完全落地的业务流程
- 对已存在接口字段的删除和改名必须谨慎，优先追加和兼容
